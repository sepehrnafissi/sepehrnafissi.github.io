How it's built

The SQL behind the dashboards

Each dashboard sits on SQL I write and maintain. This simplified example shows the pattern behind the plan-change and Volume / Mix % views:

  • CASE mapping rolls raw product codes into reporting product lines
  • Conditional aggregation splits changes by type in one pass
  • Window functions calculate mix % within each month
  • Partial-month exclusion keeps trends comparable

Table and column names are illustrative.

plan_changes_mix.sql
-- Plan changes by product line, with volume and mix %
WITH changes AS (
    SELECT
        DATE_TRUNC('month', change_date)          AS month,
        CASE
            WHEN product_code IN ('FB1', 'FB2')   THEN 'Fibre'
            WHEN product_code IN ('FW1', 'FW5')   THEN 'Fixed Wireless'
            WHEN product_code LIKE 'ST%'          THEN 'Satellite'
            ELSE 'Other'
        END                                       AS product_line,
        COUNT(*)                                  AS plan_changes,
        SUM(CASE WHEN change_type = 'Accretive'
                 THEN 1 ELSE 0 END)               AS accretive,
        SUM(CASE WHEN change_type = 'Dilutive'
                 THEN 1 ELSE 0 END)               AS dilutive,
        SUM(price_delta)                          AS price_impact
    FROM analytics.plan_changes
    WHERE customer_segment = 'Residential'
      -- exclude the current, partial month
      AND change_date < DATE_TRUNC('month', CURRENT_DATE)
    GROUP BY 1, 2
)
SELECT
    month,
    product_line,
    plan_changes,
    ROUND(100.0 * plan_changes
          / SUM(plan_changes) OVER (PARTITION BY month), 1)
                                                  AS mix_pct,
    ROUND(100.0 * accretive
          / NULLIF(plan_changes, 0), 1)           AS accretive_share,
    price_impact
FROM changes
ORDER BY month, product_line;
